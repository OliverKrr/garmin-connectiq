# CLAUDE.md for garmin-connectiq

An open-source monorepo of Garmin Connect IQ apps in Monkey C. So far it holds one app,
the Run Cockpit data field in `apps/run-cockpit/`, and the `justfile` hardcodes that app's
jungle and manifest paths. The repo is self-contained, so link other repos by public URL only,
never by local path.

## Build and test

- `just --list` describes every recipe. `just doctor` checks that the SDK, the target device
  and the signing key are in place, so run it first when a build fails on a fresh machine.
- `monkeyc` needs a per-developer signing key, `developer_key.der`. It is gitignored because
  each contributor generates their own with `just key`.
- The default device is `enduro3`; override it with `CIQ_DEVICE=<id>`.
- Only local builds compile. CI checks XML well-formedness and nothing else, because Garmin's MFA
  blocks the headless SDK-manager login that fetches device definitions. Verify a change with
  `just build` and `just test` (the simulator must be running) before calling it done.

## Code conventions

- Run Cockpit is a full-screen `WatchUi.DataField`. Compute geometry once in `onLayout(dc)` and
  cache it; `onUpdate(dc)` is the draw loop and allocates nothing.
- `apps/run-cockpit/manifest-beta.xml` and `store-assets/whats-new.txt` are generated by
  `just package` and `just validate-store-text`. Change their sources (`manifest.xml`,
  `CHANGELOG.md`) instead.

## Releases and Store text

`RELEASE.md` holds the release procedure, the two listings (Beta and Public, with their app ids
and dashboard links) and the tagging rules. Read it before cutting a version, touching an app id,
or editing anything in `store-assets/`.

- Update `store-assets/description.txt` in the same change as any setting, feature or default it
  documents. It is the Store description, pasted verbatim, so a release with a stale description
  is incomplete. It holds plain text only, with the pitch and repo link first, since about 400
  characters show before the fold.
- Store text fields take at most 4000 printable ASCII characters and reject `<` and `>`.
  `just validate-store-text` enforces this, and `just package` runs it. When the generated
  What's New grows too long, compact old `CHANGELOG.md` entries rather than raising the limit.
- Store screenshots in `store-assets/screenshots/` are on-watch captures. For the simulator
  fallback, follow `docs/store-screenshots.md` and revert its temporary source patches before
  any commit.

**Guardrail.** Packaging (`just release`, `just package`, `just tag`) is local and safe to run.
Everything outward-facing belongs to the user: the Store upload (a manual dashboard step, there
is no API), `git push` of a tag, and `just github-release`. Hand over the built `.iq` and never
report the app as published.
